<objective>
Build `static/overlay-render.js`: the ONE shared score-to-DOM renderer that fills the 11-02 lower-third skeleton. It (1) reproduces `render_overlay_text`'s per-discipline field selection plus the `_clean`/`_get` sanitize plus the `sct`/`SCT` alias, writing every value via `textContent` (the HTML-context escape — the plain-text `_clean` alone is NOT sufficient for an HTML sink); (2) runs the offset-cancellation client timer (T&F/freestyle count down and freeze at "Tempo"; agility counts up in `SS.hh` past SCT) using `server_now` so it is correct across machine clock skew; (3) runs the gen-age freshness watchdog that STOPS the timer and degrades on stale; (4) triggers the events-only animations (enter/exit/pulse). This is the milestone's single highest-risk new behavior (the timer) plus the HIGH-severity HTML-injection sink.
Output: `overlay-render.js` plus a served-JS/behavior test asserting sanitize parity, the skew formula, per-discipline format, freeze/overtime, stale-stops-timer, and the no-innerHTML sink.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator score input → overlay HTML DOM | `ScoreDoc.fields` values (operator-typed) flow into the broadcast overlay DOM. This is the HIGH-severity HTML-injection sink for this phase. |
| console clock ↔ OBS-box clock | The timer reads `started_at`/`server_now` (console clock) on a possibly different OBS machine clock — skew is the highest-risk timer bug. |
| live data freshness ↔ on-air liveness | A dead console/LAN must not present a frozen timer/score as live (stale-as-live). |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|

This is the dominant phase threat and is called out explicitly. |

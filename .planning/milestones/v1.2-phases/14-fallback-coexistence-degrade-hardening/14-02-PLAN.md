<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> console -> OBS overlay | operator-entered score values + branding cross into the broadcast HTML/JS sink (untrusted text) |
| tablet network -> console | concurrent `/overlay-json` GETs (a poll storm) contend with the safety-critical `/command` override on the lone WSGI worker |
| dead console -> OBS read-from-file | `overlay.txt` on disk is the fallback airing path when the console stops answering |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-xss | Tampering / Elevation | operator score value / `event_name` / `logo` injected as markup in the CEF overlay | mitigate | `textContent` sink (never `innerHTML`) for score values + Jinja autoescape for `event_name`/`logo`; `test_overlay_html_sink_gate.py` asserts both the JS `innerHTML` absence and the Jinja-escaped branding (V5 Input Validation / Output Encoding) |
| T-14-dos | Denial of Service | `/overlay-json` poll storm starves `POST /command` | mitigate | `threaded=True` werkzeug/waitress so a GET flood cannot block the lone worker; `test_overlay_poll_storm.py` proves `POST /command < 1.0s` under 8 concurrent `/overlay-json` GETs AND the override is written |
| T-14-fallback | Tampering (broadcast integrity) | a second `overlay.txt` writer clears the last score on death | mitigate | Single-writer property (POST /score is the SOLE writer); `test_overlay_fallback_gate.py` asserts the last score persists after a simulated death and the test adds NO second writer |
| T-14-iso | Elevation / DoS | `segugio.ui` import surface (RBT-07) | mitigate | All gates use Flask test_client / werkzeug only (no heavy import); `test_imports.py` run per task commit keeps the console import surface clean |
</threat_model>

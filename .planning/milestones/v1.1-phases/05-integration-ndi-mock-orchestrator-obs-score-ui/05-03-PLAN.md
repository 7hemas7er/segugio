<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| orchestrator → obs-websocket (localhost) | The control channel to OBS; a websocket drop / OBS restart is the realistic fault, not a remote attacker on a localhost tool. |
| score file → OBS read-from-file text source | The overlay string OBS reads; its content/path is constrained by the score manager (05-05), not this plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Denial of Service | Websocket drop mid-event mutes the director | mitigate | Persistent connection w/ reconnect+reauth; every OBS call wrapped → coast, never crash (RBT-04). Pitfall 4. |
| T-05-03-02 | Tampering | Wrong-kind text input / removed v5 request (SetTextGDIPlusProperties) | mitigate | Use read-from-file primary + set_input_settings({"text":...}) generic field; never hardcode the input kind; v5 client only. Pitfall 5. |
| T-05-03-03 | Information Disclosure | obs-websocket password in code | mitigate | Password injected via the controller constructor (config/env on the Windows box), never committed; the localhost/dedicated-LAN bind is the documented trust boundary. |
</threat_model>

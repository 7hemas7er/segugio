<objective>
Build the opcomm leaf primitives for the preview channel — the binary atomic writer, the typed sidecar record, the safe-default read/write boundary, and the additive config sub-model. This is RESEARCH "Build Order" steps 1 + 2 plus the `PreviewParams` config seed. Everything here is stdlib-only / pydantic-only and keeps the lazy-import boundary intact (no cv2/numpy/heavy imports cross into `opcomm`).

Purpose: This plan realizes D-01's transport choice — the preview channel is the EXISTING atomic-file opcomm channel extended with bytes (`atomic_write_bytes`) + one typed sidecar (`PreviewDoc`/`preview.json`), NOT a new IPC (no MJPEG/WebSocket/network server on the never-crash director). These four symbols (`atomic_write_bytes`, `PreviewDoc`, `read_preview`/`write_preview`, `PreviewParams`) are the contract the `PreviewPublisher` (plan 03) and the wiring (plan 04) consume. Defining them first means the publisher is built against a concrete, unit-tested interface — not a scavenger hunt. The `status.json`/`DirectorStatus` safety-critical channel is NOT touched (D-03).

Output: Modified `opcomm/atomic.py`, `opcomm/records.py`, `opcomm/channel.py`, `config/models.py`; new `tests/test_preview_channel.py`; extended `tests/test_atomic_io.py`.
</objective>

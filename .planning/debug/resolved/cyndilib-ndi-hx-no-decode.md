## Symptoms

- error: "No exception, no crash. Just permanent res=(0,0) / no frames. CPU ~0% (disconnected/idle coast — no busy-spin)."
- timeline: "First observed 2026-06-12 during Phase-05 live UAT, the first time the receiver was run against a real NDI HX phone source. Confirmed with NdiFrameSource and with a bare cyndilib Receiver."

## Resolution

root_cause: "cyndilib 0.1.1 bundles the NDI 6.1.1 base runtime (venv/Lib/site-packages/cyndilib/wrapper/bin/Processing.NDI.Lib.x64.dll, FileVersion 6.1.1.0) and loads it by name via os.add_dll_directory(wrapper/bin) in cyndilib/__init__.py. NDI HX (compressed) decode is performed by a SEPARATE versioned plugin — Processing.NDI.Plugins.IPCam.x64.dll (FileVersion 6.3.2.0, 'NDI-HX Library') in C:\\Program Files\\NDI\\NDI 6 Tools\\HX Driver\\x64\\ — registered globally in C:\\ProgramData\\NDI\\ndi-plugins.v1.json (NDI-HX-1 -> that DLL). cyndilib's 6.1.1 base runtime DOES discover the plugin (the discovery code + plugin name are in the bundled DLL) and the plugin DLL loads cleanly, BUT the 6.1.1 base cannot actually drive the 6.3.2-versioned HX plugin to decode — a base/plugin VERSION-PAIRING mismatch. So the receiver connects to the iPhone HX source but every VideoFrameSync has xres/yres == 0 (no decoded frames). OBS/NDI Studio Monitor decode the same phone because they pair the system 6.3.2 base runtime with the 6.3.2 HX plugin. Full/uncompressed NDI (OBS PGM) decodes through cyndilib's 6.1.1 base fine because uncompressed NDI needs no plugin."
fix: "PROPOSED (non-destructive, reversible, NO site-packages edit, NO dependency bump): in src/segugio/ndi/ndi_source.py, preload the system NDI 6.3.2 base runtime (Processing.NDI.Lib.x64.dll) by absolute path via ctypes.WinDLL BEFORE the first cyndilib import (at the top of _receiver_loop). Windows then resolves cyndilib's by-name import of Processing.NDI.Lib.x64.dll to the already-loaded 6.3.2 module — pairing the 6.3.2 base with the 6.3.2 HX plugin, exactly the config OBS/Studio Monitor use. Locate the runtime via NDI_RUNTIME_DIR_V6 env (set on this box to C:\\Program Files\\NDI\\NDI 6 Tools\\Runtime) with fallback to standard install paths; silent no-op (keep bundled 6.1.1) if absent — preserving the verified mock-clip + OBS-PGM paths on systems without the system runtime. PROVEN to bind to 6.3.2; live HX-decode verification PENDING (CHECKPOINT)."
verification: "SELF-VERIFIED (headless, no live phone): (1) src/segugio/ndi/ndi_source.py imports with NO cyndilib loaded (lazy boundary intact). (2) _prefer_system_ndi_runtime() returns C:\\Program Files\\NDI\\NDI 6 Tools\\Runtime\\Processing.NDI.Lib.x64.dll and is idempotent (2nd call -> None). (3) After preload + import cyndilib + Finder(), the ONLY base runtime loaded in-process is the system 6.3.2.0; the bundled 6.1.1 is never loaded. (4) Full headless suite: 319 passed, 7 skipped, 2 deselected (the @pytest.mark.ndi live tests) — no regression. PENDING LIVE (CHECKPOINT, requires iPhone NDI Camera view active): confirm video_frame.xres/yres > 0 and BGR frames flow from the HX phone with the fix; confirm OBS-PGM full-NDI path still decodes (no regression). LIVE-VERIFIED PASS (2026-06-12): tools/verify_ndi_hx_decode.py against the live iPhone 'LOCALHOST (iPhone Camera for OBS Studio App)' with the fix — reads=1924, decoded(res>0)=1772, max_res=1920x1080. cyndilib NOW DECODES NDI|HX. Version-pairing hypothesis CONFIRMED; fix works."

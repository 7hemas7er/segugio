# Phase 16 — UI Design Contract

> Visual and interaction contract for the dedicated `/score-entry` page and the shared `score-entry.js` component. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** the EXISTING console design system in `src/segugio/ui/templates/console.html` (D-10 — REUSE its CSS variables/palette/spacing/typography). This phase ADDS contracts only for the NEW surfaces (throw list, advisory total, per-field validation chips, publish banner). It does NOT re-invent the token set the console already ships.
>
> **Scope fence (do NOT over-spec):** Phase 16's `/score-entry` is **clean and usable, NOT pixel-polished** (D-10). Full tablet-first hardening — ≥16px anti-zoom inputs as an enforced contract, focus-trap, offline/no-CDN asset audit, explicit danger-styled publish button, localStorage reload-safe state — is **Phase 17 (SCE-04 / SCC-05)**. Items below tagged `[P17]` are noted for continuity only and MUST NOT be built here. The throw-list *entry* itself (D-01) IS in scope; only its reload-safe persistence is deferred.

## Spacing Scale

Reuse the console's documented 4px-multiple scale verbatim (`console.html` `:root` comment: "4px-multiple spacing scale … xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48"). All values are multiples of 4.

| Token | Value | Usage (this phase) |
|-------|-------|--------------------|
| xs | 4px | Icon-to-text gap; validation-chip inline padding; label-to-input gap (`margin: 8px 0 4px` already in console) |
| sm | 8px | Gap between throw-row cells (`.row { gap: 8px }`); spacing between stacked throw rows; chip vertical rhythm |
| md | 16px | Default element/section spacing; `fieldset`/card padding; input padding; page body padding |
| lg | 24px | Gap between major page sections (discipline block ↔ throw list ↔ total ↔ publish) |
| xl | 32px | Reserved — wide-screen layout gaps only if the page goes two-column (single-column is fine in P16) |
| 2xl | 48px | Reserved — not expected on this calm single-form page |

Exceptions:
- **Tap-target floors (carried from console, not new):** interactive controls keep `min-height: 44px` (buttons, add/remove-throw buttons) / `48px` (primary publish + large inputs) and inputs keep `padding: 16px`. These are min-heights, not spacing-scale violations.
- The full ≥16px-input anti-zoom contract is `[P17]`; in P16 simply inherit the console's `input { font-size: 1rem }` (already ≥16px) — do not regress below it, but the formal anti-zoom audit is P17.

## Typography

Reuse the console's locked type system **exactly 4 sizes, weights 400 + 700 ONLY** (console comment: "exactly 4 sizes, weights 400 + 700 ONLY (no 500, no 600)"). Body line-height 1.5–1.6, heading 1.2 (both already in console). Do NOT introduce a 5th size or a 500/600 weight.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (page title `h1`, "Inserimento punteggio") | 1.25rem (20px) | 700 | 1.2 |
| Heading (`legend` / card `h2` section labels, e.g. "Lanci", "Totale advisory") | 0.875rem (14px) | 700 | 1.2 |
| Body / input text (field values, throw-row controls, banner text) | 1rem (16px) | 400 | 1.5 |
| Micro / hint + validation-chip + advisory-total caption ("non ufficiale") | 0.75rem (12px) | 400 (chips/captions) · 700 (emphatic micro labels like `.freshness`) | 1.4 |

Notes:
- The **advisory running total NUMBER** may render at the Display size (20px, 700, `font-variant-numeric: tabular-nums` — reuse `.tabular`) so it reads as the headline of the form; its "advisory / non ufficiale" caption renders at Micro (12px). The number staying tabular prevents width-jitter as the operator types (D-02 live recompute).
- Validation-error chip text = Micro (12px), weight 400, in the destructive hue (see Color). Field labels stay the console's `label` style (14px / 700 / `#b9b9b9`).

## Color

Reuse the console's recomputed dark palette verbatim (`console.html` `:root color-scheme: dark` + the Phase-9 status palette). 60/30/10 split below maps the console's existing roles onto this page — no new hues are introduced except by reusing the console's already-defined semantic greens/reds.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#14161a` | Page background (`body`), the calm surface behind the form |
| Secondary (30%) | `#1a1d22` (cards) · `#1d2026` (input/bar wells) · `#333` borders | `fieldset` / `.sidebar-block` card surfaces; `input`/`select` fills; throw-row container wells; section borders |
| Accent (10%) | `#2d6cdf` | The PRIMARY publish button ("Manda in onda") and the "+ Aggiungi lancio" add-throw button background; the active/focused input border. RESERVED to these only |
| Destructive | `#9b2c2c` | Reserved — see note. NOT used for the publish button in P16 (D-04: always-enabled, neutral-accent; the explicit danger-styled publish is `[P17]`) |

Accent reserved for (explicit list — never "all interactive elements"):
- The single **primary publish action** ("Manda in onda" / "Pubblica punteggio").
- The **"+ Aggiungi lancio"** add-throw button (the headline repeatable affordance, D-01).
- The **focused-input border** (`#2d6cdf` on `:focus` — a single accent touch, optional polish).
- Everything else (remove-throw button, discipline `<select>`, secondary controls) uses the console's neutral `#3a3f47` (`.secondary`) or default input chrome.

Semantic colors (reused console hues, redundant-channel encoding — never color-only):
- **Success banner ("✓ In onda")** — green `#34D399` accent (the console LIVE green) + the "✓" glyph + the word "In onda". Three redundant channels (hue + glyph + text), so it reads in grayscale (the console's accessibility convention).
- **Error banner / per-field chip** — `#FF6B6B` (the console MORTO/feed-dead red) for the chip text/left-border + an explicit error word ("Errore", the field name, "punteggio precedente invariato"). Never red-fill-only.
- **Advisory-total caption** — neutral `#b9b9b9` (the console hint/secondary-text gray); the total is deliberately NOT colored as authoritative (D-02: explicitly non-authoritative).
- `#9b2c2c` (button danger) stays reserved for genuinely destructive buttons; in P16 the only "remove" action (delete a throw row) is **low-stakes, in-session, reversible-by-re-adding** → it uses the neutral `.secondary` gray, NOT danger red. No destructive confirmation dialog in this phase.

## Copywriting Contract

All copy is **Italian** (matches the existing console — `console.html` uses "Punteggio", "Aggiorna punteggio", "Avvia run", "agg. 0s fa", etc.). Tone: clear, calm, operator-on-a-field. Favor clarity over density (CONTEXT §Specifics).

| Element | Copy |
|---------|------|
| Page title (Display) | `Inserimento punteggio` |
| Primary CTA | `Manda in onda` (verb + the broadcast outcome the operator cares about; button always enabled per D-04). Acceptable alias: `Pubblica punteggio` |
| Discipline selector label | `Disciplina` (reuse console). Options derived from the injected profile (D-06): disc-dog → `Disc — Toss & Fetch` + `Disc — Freestyle`; agility → `Agility`. NO third free option when the sport doesn't offer it |
| Add-throw affordance | `+ Aggiungi lancio` (D-01 headline interaction) |
| Remove-throw affordance | icon-only trash/`×` button with `aria-label="Rimuovi lancio"` (no visible text needed; ≥44px tap target) |
| Throw-row field labels | `Zona` (the zone band select) · `Al volo` (midair bonus checkbox) · `Corridoio` (corridor bonus checkbox) — Italian for the `score_calc` `midair`/`corridor` flags |
| Advisory total label + caption | Label `Totale (provvisorio)`; caption directly beneath: `Calcolo live — non ufficiale. Il punteggio in onda è ricalcolato dal server.` (D-02: explicitly non-authoritative). For best-5-of-N show e.g. `Migliori 5 di {N} lanci` as a sub-caption |
| Empty state — throw list (disc T&F) | Heading: `Nessun lancio` · Body: `Aggiungi il primo lancio per iniziare a calcolare il punteggio.` (with the `+ Aggiungi lancio` button immediately below) |
| Empty state — total (before any input) | `—` (em-dash, the console's established "no value yet" convention; not the literal text "0") |
| Per-field validation error (on blur / on submit, D-03) | The server's `score_calc.validate()` message verbatim, rendered as a chip under the field. Advisory client copy mirrors it. Example shape: `{nome campo}: valore non valido` — but the AUTHORITATIVE wording is whatever `score_calc.validate` returns (D-05a); the UI is a passthrough, never a second copy source |
| Publish result — success (2xx) | `✓ In onda` (D-05; persistent inline banner, success green, stays until next action) |
| Publish result — rejected (400) | Banner: `Errore — punteggio precedente invariato` (D-05: prev on-air untouched is a broadcast-integrity guarantee, not a nicety) + the server's per-field errors mapped onto each offending field as chips |
| Destructive confirmation | **None in this phase.** Removing a throw row is low-stakes/in-session/reversible → no confirm dialog. The genuinely destructive console action ("Ferma run") lives in `console.html`, untouched here. The explicit danger-styled publish guard is `[P17]` |

Copy rules:
- **XSS-safe rendering (mandatory, RESEARCH §Security / Pitfall 5):** ALL operator free-text values (e.g. freestyle `nome`, and any value echoed back from the server) render via `textContent` / `createTextNode` — NEVER `innerHTML`, never string-built markup, never Jinja `| safe`. Static labels/icons may use `innerHTML` of STATIC markup only (the console `icon()` convention). A served-JS test asserts no `innerHTML` sink for operator values (RESEARCH test map: `test_no_innerhtml_sink`).
- The advisory total and the on-air banner must never claim authority the client doesn't have — caption wording ("non ufficiale", "ricalcolato dal server") is load-bearing (D-02 / D-05a).

## Component & Interaction Inventory (this phase's UI surfaces)

> The contracts the executor implements in `score-entry.js` + `templates/score-entry.html`. Each reuses the console's tokens above.

### 1. Discipline block (SCE-02 / D-06)
- A single `Disciplina` `<select>` whose options come from `cfg.disciplines` (injected, D-07). disc-dog → 2 options; agility → 1 option (render as a static label, not a 1-item dropdown, when there is only one — calmer).
- Changing discipline swaps the visible field set (the console `.campi` show/hide toggle pattern, reused). Only the active discipline's fields are collected on submit.

### 2. Disc Toss&Fetch repeatable throw list (D-01 — the headline UX)
- A vertical list of **throw rows**. Each row = `[ Zona <select> ][ ☐ Al volo ][ ☐ Corridoio ][ × remove ]`, laid out with `.row { display:flex; gap:8px }` (console), wrapping gracefully on narrow widths.
- **Add affordance:** a full-width `+ Aggiungi lancio` button (accent `#2d6cdf`) below the list. **Remove affordance:** a per-row icon-only `×` button (neutral `.secondary`, `aria-label="Rimuovi lancio"`, ≥44px).
- The list is **in-session only** (D-01a — lost on reload; localStorage restore is `[P17]`, MUST NOT be built here).
- Each row is keyboard-reachable and tap-friendly (≥44px controls). Rows visually separated by an 8px gap / a `#222` divider (console `.hist-row` border convention) — do not box each row in a heavy border (keep it light, the page is calm).
- **Best-5-of-N:** when `cfg.profile.count_best_n` is set, the advisory total shows the best-N selection (e.g. caption `Migliori 5 di {N}`); rows NOT counted toward the best-5 may be subtly de-emphasized (optional, `opacity: 0.55` — the console's "not-primary" treatment) but MUST remain fully editable.

### 3. Freestyle fields (SCE-02)
- 4 category number inputs (from `cfg.profile.freestyle_cats`) + a manual `adjustment` input + a free-text `nome` (rendered/echoed via `textContent` only — XSS). Labels in Italian. The console hint "usa il punto (.) per i decimali" is reused for decimal inputs.

### 4. Agility fields (SCE-02)
- `Tempo` / `SCT` (mm:ss.cc, decimal inputmode) + `course_faults` OR `course_deductions` (picked from `cfg.profile.agility_model`) + an `Eliminato` checkbox (`eliminated`). Field NAMES match the `score_calc` contract, NOT the legacy console flat keys (RESEARCH Pitfall 4).

### 5. Live advisory running total (SCE-03 / D-02)
- A prominent `Totale (provvisorio)` readout, tabular-nums, recomputed **in place** (`textContent`, never node-rebuild — RESEARCH Performance Trap) on every `input` event via `score-calc.js`. Caption "Calcolo live — non ufficiale…" always visible. Neutral color (not authoritative green).

### 6. Per-field validation (SCE-05 / D-03)
- Errors appear **on blur** per field (quiet while typing) as a Micro red chip under the field, and are re-validated on submit-attempt. Advisory source = `score-calc.js .validate`; AUTHORITATIVE source on a 400 = the server error list (D-05a). The publish button is **always enabled** (D-04) — never disabled/gated client-side.

### 7. Persistent publish banner (SCC-01 / D-05)
- A single `#publish-banner` region (NOT a transient toast). 2xx → success green "✓ In onda". 400 → error red "Errore — punteggio precedente invariato" + per-field chips. The banner **stays visible until the next action** (a live operator must not miss it). Reuse the success-green/error-red console hues with redundant glyph+text channels.

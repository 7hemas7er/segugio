<objective>
Build the `PreviewPublisher` daemon thread — RESEARCH "Build Order" step 3. This is the off-tick engine: a latest-only single-slot mailbox (`offer`/`_drain`), an own daemon loop (`_run`) at ~`1/fps` cadence, and a `_publish` method that does the per-camera `cv2.resize` -> `cv2.imencode(".jpg")` -> `atomic_write_bytes(..., fsync=False)` plus the full D-07 "why"-payload `PreviewDoc` -> `write_preview(preview.json)`. Every publish coasts on fault (RBT-04 extended). `cv2`/`numpy` import lazily INSIDE `_publish` so the class imports with the heavy stack absent.

Purpose: This is the only genuinely new construct in Phase 7 — and even it composes existing primitives (RBT-04 coast + Lock-mailbox + `atomic_write_bytes` + `write_preview` + `PreviewDoc`). The mailbox guarantees the tick never waits (the single load-bearing latency invariant gate-1 will prove in plan 04). It is built and headless-unit-tested here with an INJECTED fake encoder — no real cv2/GPU needed — against the plan-01 contract, so plan 04 only has to wire it.

Output: New `src/segugio/orchestrator/preview.py`; new `tests/test_preview_publisher.py`.
</objective>

| Boundary | Description |
|----------|-------------|
| tick thread -> publisher mailbox | the tick offers a dict ref under a short lock; the publisher reads it on its own clock. The tick never waits on the publisher. |
| publisher thread -> opcomm/preview/ files | the publisher writes JPEGs + preview.json; the console reads them in Phase 8. No untrusted input parsed on the write side. |

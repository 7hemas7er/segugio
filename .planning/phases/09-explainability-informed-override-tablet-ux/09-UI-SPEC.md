## Spacing Scale

The existing console uses `rem`-based padding (`1rem` body, `0.8rem` fieldset, `0.5rem` gaps). Phase 9 declares an explicit **4px-multiple** scale; map `rem` to px at the root 16px and use these tokens for all new Phase-9 CSS. Keep the existing values where they already land on the scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding, leaderboard bar inner gap |
| sm | 8px | **Minimum inter-target spacing (touch)**, compact element gaps, tile gap |
| md | 16px | Default element spacing, body padding (`1rem`), input padding block |
| lg | 24px | Section padding, sidebar block separation, leaderboard bar height (lower bound) |
| xl | 32px | Layout gaps, sidebar↔grid gutter, leaderboard bar height (upper bound) |
| 2xl | 48px | Major section breaks; **destructive / stepper minimum touch target** |
| 3xl | 64px | Page-level spacing reserve |

**Exceptions (declared, all multiples of 4 or HIG-mandated):**
- **Touch target floor = 44×44 CSS px** (Apple HIG, authoritative). The whole camera tile and every override/run/score control must meet this. 44 is not on the 4-grid but is a hard accessibility constant — it overrides the grid for minimum hit area.
- **Destructive / critical controls + score steppers ≥ 48×48 CSS px** ("Ferma run", "Rilascia (auto)", any +/- stepper).
- **Inter-target spacing ≥ 8px** (sm); separate undo ("Rilascia") from score-confirm by **≥ 16px** (md).
- Safe-area insets via `env(safe-area-inset-*)` are device-driven, not grid values (see touch contract).

## Typography

System font, exactly **4 sizes** and **2 weights**. All sizes are the RENDERED computed size; **score `<input>` must compute ≥ 16px** to block iOS focus-zoom (the template's `1rem` already satisfies this — never drop inputs to `0.9rem`).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (page H1, "ON AIR" banner) | 20px (1.25rem) | 700 (bold) | 1.2 |
| Body / inputs / buttons / reason text | 16px (1rem) | 400 (regular) | 1.5 |
| Label / leaderboard cam-label / badge / history row | 14px (0.875rem) | 700 (bold) for labels & badges; 400 for history body | 1.4 |
| Micro (leaderboard value, freshness stamp, track-id) | 12px (0.75rem) | 700 (bold, tabular) | 1.3 |

- Weights: 400 regular + 700 bold only — no 500, no 600. Every emphatic role (Display/H1/ON-AIR, Label, badges, leaderboard cam-label, Micro values) renders at **700**; body, inputs, buttons, reason text, and history body render at **400**.
- **Implementation delta:** the existing template's `legend { font-weight: 600 }` becomes `font-weight: 700` (legend is an emphatic section label, so it reads strong on the regia at a glance — matching the existing `700` on `.onair`). The existing `.onair`/Display 700 is unchanged. No 500 or 600 may appear anywhere in the inline CSS.
- Leaderboard numeric values and the freshness/age stamp use **tabular figures** (`font-variant-numeric: tabular-nums`) so 2-decimal scores (`.81`) don't jitter column width as they update.
- Body line-height 1.5; heading/Display 1.2 (existing `#stato` 1.6 may stay — it is a status block, not body copy).

## Color

**Reconciliation decision (resolved):** adopt the contrast-verified researched status palette **but on the EXISTING `#14161a` background family** (NOT the researched `#11151c`). All ratios below were **recomputed against `#14161a`** (WCAG sRGB linearization, no rounding up). The legacy LIVE-red `#b23b3b` border (contrast 3.09:1 on `#14161a` — below the 3:1 floor for a non-text UI border only by a hair, and red/green is the primary CVD confusion axis) is **retired for status semantics**: LIVE becomes green, MORTO keeps a red hue but is primarily a **dim + desaturate** treatment, and red is no longer the LIVE signal. Status is encoded by **3 redundant channels** (hue + border-style/shape + text label) so it is grayscale-safe (WCAG 1.4.1).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#14161a` | Page background, multiview area (existing) |
| Secondary (30%) | `#1d2026` panel / `#222` chips / `#1a1d22` sidebar | Sidebar column, cards, input bg, badge bg, fieldsets |
| Accent (10%) | `#2d6cdf` | **Primary action only** — "Aggiorna punteggio" submit, "Avvia run". Reserved list below. |
| Destructive | `#9b2c2c` | **"Ferma run" only** (a true destructive/stop action). NOT used for LIVE status anymore. |

**Destructive contrast (resolved):** white `#fff` text on `#9b2c2c` ≈ **5.3:1** — clears the 4.5:1 normal-text threshold (the legacy `#b23b3b` gave only ≈4.14:1 white-on-bg and is retired for the button). `#9b2c2c` as a border/large element against the `#14161a` page background ≈ **3.4:1** — clears the ≥3:1 non-text floor. **Implementation delta:** the existing template's `.danger { background:#b23b3b }` becomes `.danger { background:#9b2c2c }`.

**Body / neutral text** (existing, verified): body text `#e8e8e8` (14.78:1), muted label `#b9b9b9` (9.23:1). Phase-9 status LABEL text renders in off-white `#E6E9EF` (14.89:1) when a hue would be borderline; the hue lives on the border/badge.

**Status palette — recomputed contrast vs `#14161a` (and vs `#1d2026` secondary surface):**

| State | Hue | Ratio vs `#14161a` | Ratio vs `#1d2026` | Min target | Non-color cues (mandatory, load-bearing) |
|-------|-----|--------------------|---------------------|-----------|-------------------------------------------|
| LIVE (auto) | `#34D399` green | **9.42:1** | 8.49:1 | border/icon ≥3:1, label ≥4.5:1 | **solid** border + `●` + text "LIVE" |
| FORZATA (override) | `#F0B429` amber | **9.72:1** | 8.75:1 | ≥3:1 / ≥4.5:1 | **solid** border + 🔒 lock + "FORZATA" + corner ribbon/stripe |
| MORTO (dead/stale feed) | `#FF6B6B` red | **6.53:1** | 5.88:1 | ≥3:1 / ≥4.5:1 | **dim+desaturate tile to 50–60% opacity** + `✕` + "MORTO" |
| auto-wants (WHY-04) | `#56B4E9` blue | **7.85:1** | 7.07:1 | ≥3:1 / ≥4.5:1 | **dashed** border + `▸` chevron + "auto →" tag |
| coast (leaderboard) | `#9CA3AF` neutral | **7.13:1** | 6.43:1 | ≥3:1 | **hatched** bar fill + `◐` |
| lost (leaderboard) | `#6B7280` dim-gray | **3.75:1** | 3.38:1 | non-text / de-emphasized ONLY | **empty/outline** bar + `··` + "lost". Render its LABEL in `#E6E9EF`, never the gray as text. |

**Accent (`#2d6cdf`) reserved for — explicit list (never "all interactive"):**
- the score-form submit button ("Aggiorna punteggio")
- the "Avvia run" button

Everything else interactive uses neutral/secondary surfaces: tiles (status hue governs their border), "Rilascia (auto)" = secondary (`#3a3f47`, large), "Ferma run" = destructive (`#9b2c2c`). The force gesture is the **tile itself** (no accent-colored force button — the blind text force buttons are removed, D-02).

Green(LIVE) and red(MORTO) MUST differ by border-style + icon + label as well as hue (CVD). LIVE = solid green; MORTO = dim/desaturate (no solid colored border) — the treatments are categorically different, not just two hues.

## Phase-9 Interaction & Component Contracts

> The base UI-SPEC template has no slot for the phase-specific visual + interaction contracts. This section is prescriptive (exact px / hex / attributes / event names). Downstream planner + executor implement directly from here. Every clause marked **[VERIFIED]** is lifted from `09-UI-RESEARCH.md` (adversarially verified, 2026-06-13); **[ASSUMED]** items must be re-validated on the physical target iPad in Wave 0 (see §Wave-0 checklist) but are still implemented to these defaults.

### Layout (UXT-01, D-01) — Multiview + sidebar, landscape-first

- **Two-region landscape layout:** dominant **multiview grid on the LEFT** (reuse the existing `.multiview` CSS-grid: `repeat(auto-fit, minmax(240px, 1fr))`, tiles `aspect-ratio: 16/9`, gap `sm`/8px), and a **fixed right sidebar column** (`xl`/32px gutter). Sidebar top→bottom order (D-01, approved mockup): **(1) Reason** (WHY-01) → **(2) Score leaderboard** (WHY-02) → **(3) Auto-wants hint** (WHY-04) → **(4) Switch-history strip** (MVW-05) → **(5) Score form + live preview** (SCV-01).
- **Reflow:** below a landscape-tablet width the sidebar drops **below** the grid (single column); the grid stays first. The live cam + reason must stay visible (D-01 criterion).
- **Sidebar width:** ~320–360px on landscape iPad; never narrower than the leaderboard's full-width bar track + 2-decimal value.
- **Side configurability** `[ASSUMED]`: the bottom-trailing control cluster (undo + score form) side (left/right) SHOULD be switchable for grip; default right.

### Viewport & touch (UXT-01) — [VERIFIED HIGH]

- **Viewport meta** (replace the existing): `width=device-width, initial-scale=1, viewport-fit=cover`. **FORBID** `user-scalable=no` / `maximum-scale=1` (iOS ignores them AND fails WCAG 1.4.4/1.4.10).
- **`touch-action: manipulation`** on `body` + all interactive elements — kills double-tap-zoom and the 300ms click delay (Safari 13+). Do **not** rely on FastClick.
- Pair `viewport-fit=cover` with **`env(safe-area-inset-*)` padding** on the bottom control cluster so it clears the home indicator.
- On tiles/buttons/labels (NOT on the score numeric inputs): `-webkit-user-select:none; user-select:none; -webkit-touch-callout:none; -webkit-tap-highlight-color:transparent`. Because the native highlight is removed, **provide an explicit `:active` visual** on every tap target.
- **Tap targets ≥ 44×44 CSS px**; destructive/critical + steppers **≥ 48px**; inter-target spacing **≥ 8px**, undo↔confirm **≥ 16px**.
- **Bind force + undo to the standard `click` event.** FORBID `touchstart`/`touchend` synthetic-click handlers (double-fire live actions on current iOS). Pointer Events only if hold/drag is ever added.
- **Reachability** `[ASSUMED]`: dock **"Rilascia (auto)"** + the one-handed score form to the **bottom-trailing thumb arc** (safe-area padded); keep freshness + status read-outs at the **top**.

### Multiview tile states (D-04, WHY-04) — 3 redundant channels, grayscale-safe [VERIFIED]

Each tile is a `role="button"` element (whole tile = tap-to-force, D-02). State is set by toggling classes on the tile (driven by `/status` `live_cam`+`alive`, `/preview` `auto_candidate`, and the freshness watchdog). Border-style is **load-bearing**, not decorative.

| State | Border | Icon/shape | Label | Extra |
|-------|--------|-----------|-------|-------|
| LIVE (auto) | **solid** `3px #34D399` | `●` | "LIVE" | green badge |
| FORZATA (override) | **solid** `3px #F0B429` | 🔒 lock | "FORZATA" | amber corner ribbon/stripe |
| MORTO (dead/stale) | none (dim) | `✕` | "MORTO" | tile `opacity: 0.5–0.6` + desaturate; **hide bbox overlay** |
| auto-wants (WHY-04) | **dashed** `3px #56B4E9` | `▸` | "auto →" tag | shown on the candidate tile **during an override** (so the operator knows when it's safe to release) |
| idle/cold | `3px #333` (existing neutral) | — | cam id | until first verified-fresh frame |

- **FORZATA vs LIVE distinction is mandatory** — an operator override (`reason=="override"` AND `live_cam==cam`) shows FORZATA (amber, lock, ribbon), NOT LIVE. Auto-selected live shows LIVE (green, ●). These must never look the same.
- A tile may carry **auto-wants simultaneously** with another tile being FORZATA (the override target is FORZATA; the tile auto would pick is dashed-blue auto-wants).
- Tiles are `role="button"` + `aria-pressed` reflecting forced state; visible `:active`.

### Dog-lock bbox overlay (WHY-03) — [VERIFIED HIGH, zero JS letterbox math]

- Render **one inline `<svg viewBox="0 0 1 1" preserveAspectRatio="xMidYMid meet">` per tile**, positioned with the EXACT same box geometry (width/height/position, zero padding/border) as the tile's `<img>` which uses **`object-fit: contain`**. `xMidYMid meet` letterboxes identically to `object-fit:contain`, so the normalized `box=[cx,cy,w,h]` from `preview.json` becomes a plain:
  ```html
  <rect x="cx - w/2" y="cy - h/2" width="w" height="h" vector-effect="non-scaling-stroke" />
  ```
  **No JavaScript letterbox math in the live path** — the SVG engine's meet-scaling IS the alignment guarantee. Stroke `2px` in LIVE green `#34D399` (matches the lock state); fill none.
- **`box` may be `None`** → draw nothing (subject not locked this tick). Optional `track_id` label small (12px) near the box top-left — Claude's discretion, off by default.
- **Update geometry ONLY on `gen` advance** (1–4 Hz). Animate via a CSS transform on a WRAPPER element, GPU-promoted (`translateZ(0)` / `will-change:transform`); **promote only VISIBLE overlays** (iOS renders promoted layers even off-viewport → memory).
- **Hide/grey the overlay whenever its tile is STALE or MORTO** — never draw a box on a frozen/dead frame.
- **Scope:** always-on on the **live tile** (D-05); extendable to any tile whose `box` is present (Claude's discretion).
- **Div-% fallback** (document, use only if SVG repaint ever proves problematic): `s=min(Cw/imgW,Ch/imgH); Rw=imgW*s; Rh=imgH*s; ox=(Cw-Rw)/2; oy=(Ch-Rh)/2; left=ox+(cx-w/2)*Rw; top=oy+(cy-h/2)*Rh; width=w*Rw; height=h*Rh`, recomputed on `resize`+`orientationchange`+`visibilitychange`.

> ⚠ **Dependency note (STATE blocker):** the bbox depends on BoT-SORT native ReID `locked`/`track_id` stability on yolo26s. That engagement is re-verified at orchestrator startup; the overlay simply renders `box` when present and draws nothing when `None` — it must NOT assume a box is always available.

### Score leaderboard (WHY-02) — [VERIFIED]

- **Horizontal bars, height 24–32px** (`lg`–`xl`), gap ≈ half bar height (`sm`/8px). Fixed full-width track anchored at a **zero baseline**, **sorted highest-first** by `score` (or `ema`).
- Per row: **camera label left** (14px/700) · **proportional 0..1 fill** (the score) · **2-decimal value right-aligned** (12px tabular, e.g. `.81`). Matches the approved mockup `①▓▓▓ .81 / ②▓▓ .40 / ③·· lost`.
- **Fill treatment encodes track state** (from `cams[id].state`):
  - tracking → **solid** filled bar, `#34D399`-family fill + `●`
  - coast → **hatched** bar, `#9CA3AF` + `◐` + "coast"
  - lost → **empty/outline** bar, label in `#E6E9EF`, `··` + "lost"
- Data source: `preview.json` `cams[id]={score,ema,state,...}`. Empty/absent → "Nessun dato di framing".
- All cams shown (D-05, compact, always visible).

### Switch-history strip (MVW-05) — [from `cuts` ring]

- Read `preview.json` `cuts` (ring, newest-last, depth ~16). Show newest-first; **count is Claude's discretion** (suggest 5–8 to fit the sidebar).
- Per row: `"{from} → {to} · {reason-it}"` (14px), reason mapped to the same Italian reason strings as WHY-01; optionally a relative tick/age. Empty ring → "Nessun cambio recente".

### SCV-01 — live score-overlay preview (client-side, drift-guarded) [VERIFIED]

- **Mirror the 3 `render_overlay_text` f-strings in client JS, character-exact**, plus the same `_clean()` sanitize (strip CR/LF + non-printable control chars; `text.strip()`; cap at **`_MAX_FIELD_LEN = 64`**):
  - `disc_tf` → `"Prese: {prese}  Zona: {zona}  Totale: {totale}"`
  - `disc_freestyle` → `"{nome}  Timer: {timer}"`
  - `agility` → `"Tempo: {tempo} / SCT: {sct}  Faults: {faults}"`
  - (note the **double space** in the originals — replicate exactly)
- **Debounce 150–250ms**; update an "Anteprima overlay" read-only display as the operator types. **NO per-keystroke round-trip** (LAN spikes on contended WiFi couple feedback to the network) and **NEVER to the orchestrator**.
- **Drift-guard:** on input `blur` AND on `submit`, call a **tiny Flask render endpoint ONCE** (allowed — Flask, not the orchestrator; reuses `render_overlay_text`) and assert `server === client`; on mismatch show **"⚠ Anteprima non allineata — verifica"**.
- **Wave-0 CI parity test:** feed identical `ScoreDoc`s to the Python `render_overlay_text` and the JS mirror; assert byte-identical output across all 3 disciplines.

### Score form (UXT-01, one-handed) — [VERIFIED]

- All score `<input>` computed font-size **≥ 16px** (template's `1rem` — preserve; never `0.9rem` on inputs) to block iOS focus-zoom. The threshold is the RENDERED size.
- **`type="text"` + `inputmode`, NEVER `type="number"`** (iOS Safari `type=number` raises no numeric keypad and silently drops non-numeric input). Existing fields already use `inputmode` — keep:
  - integer fields (Prese, Totale, Faults) → `inputmode="numeric"`
  - decimal fields (Tempo, SCT, Timer) → `inputmode="decimal"`
- **`enterkeyhint="next"`** on all fields except the last; **`"send"`** (or `"done"`) on the final field.
- **Italian decimal handling:** the iOS decimal keypad separator is unreliable (interchangeable `,`/`.`; documented iPadOS 26.2+ regression). The renderer is verbatim so DISPLAY is safe, but **any client-side numeric validation MUST accept BOTH `,` and `.`**; UI helper copy steers operators to `.` ("usa il punto (.) per i decimali").

### Lifecycle, freshness & sleep/wake resume (UXT-03) — [VERIFIED, load-bearing]

- **Lifecycle wiring (mandatory):** register on BOTH `document` `visibilitychange` (read `document.visibilityState`) AND `window` `pageshow`/`pagehide` (read `event.persisted`). **Do NOT use** `focus`/`blur`, `unload`, or the Page-Lifecycle `freeze`/`resume` events — Safari iOS through 26.5 does not implement `freeze`/`resume` (caniuse, verified).
- **Resume fetch MUST be deferred:** never call `fetch()` synchronously inside the visibilitychange→visible / `pageshow` handler — wrap the first resume fetch in `setTimeout(fn, ~150–250ms)` to dodge the iOS `fetch` "Load failed" bug (`TypeError`, ~20–40s window). Retry once after a further delay on failure. `[ASSUMED]` exact delay → measure Wave 0.
- **`?t=<gen>` nonce is the load-bearing refresh mechanism — NOT `Cache-Control: no-store`.** Safari is a documented outlier that may bfcache a `no-store` page and restore a frozen image without refetching; the unique `?t=<gen>` URL is what guarantees a fresh decode. `no-store` (already set server-side) is necessary but not sufficient — keep it AND the nonce.
- **Freshness is `gen`/server-timestamp-driven, NOT poll-tick-driven.** Record a `resumeAt` on wake; a tile may render LIVE only once a frame whose `gen` post-dates `resumeAt` arrives. Any frame older than the staleness window → visible **STALE / RICONNESSIONE…** overlay, never "LIVE".
- **On hide** (`visibilityState==='hidden'`): `clearInterval` (or down-shift) the poll; record hide time.
- **On resume** (`pageshow.persisted===true` OR visibilitychange→visible): immediately mark ALL tiles stale + blank/dim; tear down the old interval and start a fresh one; clear the per-tile stale overlay only when a verified-fresh frame loads.
- **Foreground staleness WATCHDOG is PRIMARY and MANDATORY** (not the lifecycle hooks): Safari does NOT fire `pagehide` on app-switch-then-kill, and `pageshow.persisted` may be `false` under memory pressure (full reload). Run the `gen`-age-vs-local-clock check on a foreground interval so a frozen frame is caught within one poll cycle even if NO lifecycle event fired. The page must reconstruct cleanly from `/status` on a COLD load. (Extend the existing `lastGen`/`lastGenAt`/`STALE_MS` mechanism + `markTiles`.)
- **Staleness threshold (Claude's discretion):** derive from `preview.fps` / `gen` advance — STALE when `gen` has not advanced within **N publish intervals** (existing `STALE_MS = PUBLISH_MS * 3` is the seed; tune to ~2–3× the publish cadence). Seed `lastGenAt` to load time, not epoch 0 (existing WR-02 guard — preserve, else the first paint falsely flags MORTO).
- **Wake Lock (note, out of strict scope):** Screen-Wake-Lock is Safari 16.4+; re-acquire on every visibilitychange→visible; if installed as a Home-Screen PWA and screen-on is required, deploy iPadOS ≥ 18.4.

### Flicker-free, leak-free `<img>` refresh (UXT-03) — [VERIFIED]

- **ONE persistent `<img>` per tile** (already in the template) + **ONE reused off-DOM `Image()` preloader per tile, created ONCE**. - **FORBID `fetch→Blob→URL.createObjectURL`** for live tiles (leak-prone on older Safari; unnecessary).
- **`gen`-gating:** only swap when polled `gen` is **strictly >** last rendered `gen`; never re-fetch the same `gen` (existing pattern — keep).
- **Hidden/off tiles** (camera dropped to SAFE / removed) → set `src` to a **1×1 transparent data-URI**, NOT `display:none` (a `display:none` eager `<img>` still holds fetched bytes + may hold a decoded bitmap). The data-URI deterministically frees it.

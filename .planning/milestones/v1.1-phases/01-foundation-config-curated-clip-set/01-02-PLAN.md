Schema (from ARCHITECTURE.md Part 3 + RESEARCH.md Code Examples):
  Role enum:        main_wide | long | low | handler_side
  Zone:             { name: str, rect: [x0,y0,x1,y1] each in [0,1], x0<x1 & y0<y1 }
  Camera:           { id, role: Role, obs_scene, is_safe: bool=False, ndi_source: str|None, zones: list[Zone] (>=1) }
  ModelConfig:      { path: Path = "yolo26s.pt", class_index: int = 16 }
  Thresholds:       { alpha, hysteresis_margin, min_dwell, debounce_N, cooldown, watchdog_timeout, track_buffer }
  framing_weights:  dict[Role, dict[zone_name, float]]
  field:            FieldProfile  (discriminated union on `sport`)

  DiscDogProfile:   { sport: Literal["disc_dog"], event, overlay_fields: list[str], framing_defaults }
  AgilityProfile:   { sport: Literal["agility"], event, overlay_fields: list[str], framing_defaults }
  FieldProfile = Annotated[DiscDogProfile | AgilityProfile, Field(discriminator="sport")]

  Config:           { field: FieldProfile, cameras: list[Camera] (>=1), framing_weights, thresholds, model }
  Cross-validator (model_validator mode="after"):
     - every zone name referenced by a camera MUST exist in framing_weights[camera.role]  (CFG-02 typo guard)
     - at least one camera has is_safe=True (SAFE fallback exists)

Loader:  load_config(path: str | Path) -> Config
     - yaml.safe_load ONLY (never yaml.load)
     - on read/parse error or ValidationError: log via loguru + raise SystemExit(2) (fail-fast, non-zero)

Overlay field sets (from FEATURES.md, used by the discipline profiles):
  disc_dog (Toss&Fetch): team, round, timer, catch_count, zone, total
  disc_dog (freestyle):  team, routine_timer, category_scores, total      (event-dependent default)
  agility:               dog, sct, running_time, faults, result

Consumers of shared test fixtures (from 01-01 conftest): valid_config_dict, tmp_config.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-provided config.yaml → process | The config file is UNTRUSTED input parsed at startup |
| config.model.path → filesystem | A path string from config is resolved as a Path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02a | Tampering / RCE | YAML parsing in loader.py | mitigate | Use `yaml.safe_load` EXCLUSIVELY (never `yaml.load` without SafeLoader). Acceptance criterion greps that `yaml.load(` appears 0 times. Arbitrary-object deserialization is the classic PyYAML RCE; safe_load eliminates it. |
| T-01-02b | Denial of Service | malformed config reaching the live loop | mitigate | Fail-fast at startup: pydantic aggregates all errors into one `ValidationError`; loader logs it and `raise SystemExit(2)`. A bad config can never reach the Phase-5 live director (CFG-01). |
| T-01-02c | Tampering | path injection via `model.path` / `cameras[].ndi_source` | mitigate | Treat `model.path` as `pathlib.Path`; never `eval`/shell-interpolate config strings. Existence/resolution of the model file is a Phase-4 load-time concern (re-verify class index vs `model.names` there), not a Phase-1 check. |
| T-01-SC | Tampering | pydantic/pyyaml installs | accept | Pre-locked, universally-known packages (installed in 01-01); no fresh installs in this plan. |
</threat_model>

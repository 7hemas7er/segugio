If OBS is down at launch (a normal field condition) `obs.connect()` raises `ConnectionError` and the process exits before the tick loop starts — breaking the most fundamental phase contract. The existing `tests/test_fault_isolation.py` passes only because its injected fakes never raise on `connect()`/`start()` — so it never exercises the startup path. This plan adds a NEW headless regression test that injects a source/obs that RAISE on start/connect and proves the loop survives and ticks. That test is what flips Truth #5 to VERIFIED on re-verification.

Purpose: restore the never-crash contract at its most exposed point (launch with OBS down) and stop cut-storms on jittery feeds (non-zero grace default), with real headless regression coverage.
Output: hardened `loop.py` startup path + guarded `ObsWsController.connect()` + additive `Thresholds.watchdog_grace` config seed + a new `tests/test_orchestrator_startup.py` regression test + a fault-reason assertion.

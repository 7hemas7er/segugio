| Boundary | Description |
|----------|-------------|
| NDI network (named sources) → receiver threads | Frames from a (mock or real) named NDI source enter the process; a frozen/stalled source is the realistic failure (75-min TTL freeze), not a malicious actor on a localhost/dedicated-LAN tool. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Spoofing/Information | False NDI liveness (frozen feed repeats last frame ~75min) | mitigate | Liveness stamped ONLY on a NEW frame (`ts != last_ts`); the watchdog (05-04) reads last_frame_ts, never receiver.is_connected(). Pitfall 1. |
| T-05-02-02 | Denial of Service | Empty/zero-resolution first frame reshape crash | mitigate | `min(xres,yres)!=0` guard before reshape; mock reproduces the zero-size skip (NDI-03). |
| T-05-02-03 | Denial of Service | A dead receiver thread silently stops a camera | mitigate | Supervised thread model; stop event + join; the orchestrator (05-06) restarts a dead thread (RBT-04). |
</threat_model>

<key_facts>
These NDI facts were validated empirically this session — treat as ground truth, do NOT re-investigate:

- SENDER pattern (mirror `mock_sender.publish_clip`): build a cyndilib `Sender(stream_name)` ONCE; `VideoSendFrame()` → `set_resolution(w, h)` from the first frame → `set_frame_rate(Fraction(fps, 1))` → `set_fourcc(FourCC.BGRA)` (FourCC lives in `cyndilib.wrapper.ndi_structs`) → `sender.set_video_frame(vf)`; then inside `with sender:` write each frame via `sender.write_video_async(cv2.cvtColor(bgr, cv2.COLOR_BGR2BGRA).reshape(-1))`. `cv2` and every `cyndilib` symbol are imported LAZILY INSIDE the function (project convention). Building the Sender ONCE (not per loop) is mandatory — re-creating it per loop makes the source flicker and trips the receiver watchdog.
- HOST PREFIX: a `Sender("FOO")` is DISCOVERABLE on the network as `"<HOST> (FOO)"`. This box's NDI host name is `MASTER` (`socket.gethostname()` returns `"Master"`; NDI uppercases it to `MASTER`). `NdiFrameSource._resolve_source` does an EXACT `source_name in finder.get_source_names()` match, so the config `ndi_source` MUST be the host-prefixed `"MASTER (...)"` form.
- DISCOVERY: plain mDNS is BROKEN on this box (Tailscale interferes). The working setup is the NDI Discovery Server on 127.0.0.1 + `%APPDATA%/NDI/ndi-config.v1.json` = `{"ndi":{"networks":{"discovery":"127.0.0.1"}}}` (already written this session). This is a RUNBOOK prerequisite, NOT something the code does.
- VENVS: run the looping sender from the CPU `venv/`; run the orchestrator from `venv312/`. Both have cyndilib+cv2+numpy. `segugio` is editable-installed in both (`from segugio.config import load_config` works directly).
- Clips ALREADY EXIST (gitignored) in `tests/fixtures/looptest/`: `cam_wide_9898282.mp4`, `cam_long_18233295.mp4`, `cam_low_16573252.mp4`, `cam_handler_32484430.mp4`. Do NOT re-download.

Flow in a `build(...)`/`main(...)` pair:
1. `load_config(args.config)` to get the camera list (lazy: import load_config at top is fine — it is light).
2. For each camera with a non-None ndi_source: derive stream = stream_name_from_ndi_source(cam.ndi_source); glob `--clips-dir` for `{cam.id}_*.{ext}` over ext in (mp4, mov, mkv, avi, webm) (case-insensitive), take the first match; if none, `logger.warning(...)` and SKIP that camera (do not abort).
3. Decode each matched clip into a list of BGR frames in a `decode_clip(path, max_width, max_seconds, fps_override) -> tuple[list, float]` helper (lazy `import cv2` inside): open `cv2.VideoCapture`, read native fps from CAP_PROP_FPS, use fps = fps_override if >0 else native (fallback to 30.0 if native is 0/NaN); read frames until exhausted; if max_seconds>0 stop after int(max_seconds*fps) frames; downscale each frame when its width exceeds max_width by scale = max_width/width keeping aspect via `cv2.resize(..., interpolation=cv2.INTER_AREA)`; release the capture; return (frames, fps). Skip with a warning if zero frames decode.
4. Startup banner (loguru, BEFORE spawning threads): print the NDI Discovery Server reminder, this box's detected host (`socket.gethostname().upper()`), and per camera: matched clip file, frame count + fps, the PUBLISHED stream name, the EXPECTED discoverable name `expected_discoverable(stream, socket.gethostname().upper())`, and the config ndi_source it must equal — `logger.warning(...)` if expected != cam.ndi_source (host mismatch; tells the user to fix config/hostname).
5. Spawn ONE daemon thread per camera (`threading.Thread(target=..., name=f"ndi-loop-{cam.id}", daemon=True)`) sharing a single `threading.Event` stop flag. Each thread runs `publish_loop(stream, frames, fps, stop)` that LAZILY imports cv2 + (Sender, VideoSendFrame, FourCC) exactly as mock_sender.publish_clip does, builds the Sender + VideoSendFrame ONCE (set_resolution from frames[0], set_frame_rate Fraction(int(round(fps)) or fps,1), set_fourcc BGRA, set_video_frame), then `with sender:` loops `while not stop.is_set():` over the frame list forever, writing `sender.write_video_async(cv2.cvtColor(bgr, cv2.COLOR_BGR2BGRA).reshape(-1))` and `time.sleep(1.0/fps)` per frame. NEVER re-create the Sender inside the loop (flicker → watchdog trip).
6. Main thread: after starting all threads, block until KeyboardInterrupt (e.g. loop `time.sleep(0.5)`); on KeyboardInterrupt set the stop event, join threads with a short timeout, log a clean shutdown, return 0.

Keep `cyndilib`/`cv2` imports strictly inside `decode_clip` and `publish_loop` (the lazy boundary). Do NOT modify mock_sender.py — reimplement the small sender setup locally so no existing source file changes.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser → /score (LAN POST) | The only path that changes what airs; untrusted client input crosses here. |
| localStorage ↔ component | Operator-typed draft persists locally; read back into the DOM on restore. |
| served JS → DOM | All rendered values cross into the page (XSS sink surface). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Tampering | localStorage draft (operator can hand-edit/corrupt the key) | mitigate | Restore reader wrapped in try/catch → empty draft, never throws (D-02 never-raise discipline); the draft is advisory-only and is NEVER the authority for what airs — only `POST /score` (recomputed server-side) changes the overlay. A tampered draft can at worst pre-fill the form, which the server still validates+recomputes (Task 2). |
| T-17-02 | Elevation of Privilege / Tampering | client-only validation bypass via direct LAN POST (PITFALLS #3) | accept (already mitigated upstream) | The authoritative `POST /score` server path (Phase 16, unchanged here) validates+recomputes; the client confirm/Enter-guard are UX integrity, not security. This plan adds NO client-side authority and does not weaken the server path. |
| T-17-03 | Tampering (XSS) | restored draft values + confirm-button label morph reaching the DOM (PITFALLS #5) | mitigate | All new sinks use `textContent`/`classList`/existing `el()` helpers — never `innerHTML`. The served-JS no-innerHTML test stays green (Task 3 acceptance). A `<script>`-laden draft value renders as inert text. |
| T-17-04 | Denial of Service / integrity | accidental on-air of a half-entered score (casual tap or Enter) | mitigate | Two-step danger-styled confirm with auto-revert (D-05) + Enter-never-publishes (D-06); the only path to air is two deliberate taps (Task 3). |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | ZERO new dependencies this phase (vanilla JS + native APIs, stdlib server). No install task exists → no package-legitimacy gate needed. |
</threat_model>

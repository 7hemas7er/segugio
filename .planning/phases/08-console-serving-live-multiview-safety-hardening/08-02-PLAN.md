<objective>
Add the HARD preview-bandwidth cap as a CONFIG-TIME guarantee (D-01/D-02): a `max_total_mbps` ceiling field on `PreviewParams` plus a `Config`-level `@model_validator(mode="after")` that computes the worst-case preview bitrate (`est_bytes_per_frame(width, quality) × 8 × fps × N_cams`) and rejects any over-cap config at startup via the existing fail-fast `SystemExit(2)` loader. This is how "the preview degrades before the NDI feeds" is guaranteed by construction — not by a runtime throttle.

Purpose: Phase 7 shipped the publish-fidelity seeds but left the HARD cap to Phase 8. WiFi contention is the #1 domain risk (3-4 phones already push 60-200 Mbps of NDI HX3); the preview byte budget must be a first-class capped resource (≤ 5-8 Mbps). Enforcing it at config-load time (CFG-01 posture) means an over-budget preview config is a startup error, not a live surprise — and there is NO moving-parts feedback loop on the never-crash side (a runtime throttle overlaps Phase-9 UXT-03 and is explicitly rejected, D-01).

Output: An extended `PreviewParams` + a sibling `Config` validator + a documented bpp-constant helper, with a test asserting the default passes AND a cranked config is rejected.
</objective>

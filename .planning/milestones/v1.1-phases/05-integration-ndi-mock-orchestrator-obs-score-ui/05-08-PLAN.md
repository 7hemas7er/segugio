<objective>
Close the two remaining HEADLESS-CLOSEABLE code-quality issues that live in separate files from the loop.py blocker (05-07), each with a real headless regression test:

- WR-04 — `atomic_write_text` (atomic.py line ~93) uses a bare `os.replace(tmp, path)` instead of the `_atomic_replace` retry that `atomic_write_json` uses. OBS reads the overlay file continuously via a read-from-file text source; on Windows, if OBS holds the file open at the instant of the swap, `os.replace` → `MoveFileEx` raises `PermissionError` (sharing violation). The overlay write must retry the swap like the JSON path already does (Pitfall 6).
- CR-02 — `NdiFrameSource._receiver_loop` (ndi_source.py lines ~114-115) busy-spins (`while not self._stop.is_set(): if not receiver.is_connected(): continue`) which pins a CPU core while disconnected, and never re-resolves a named source that was absent at thread start. The CODE FIX is headless-importable: add a short sleep on the disconnected branch and a re-resolve/reconnect attempt of the named source. The FULL behavior (near-zero CPU, real auto-reconnect on cyndilib hardware) is HARDWARE-verified (@pytest.mark.ndi) and stays human.

Purpose: harden the two real-stack robustness paths (Windows file-sharing on the overlay; CPU/auto-reconnect on the NDI receiver) with headless regression coverage, before the hardware milestone.
Output: `atomic_write_text` routed through `_atomic_replace`; `_receiver_loop` disconnected branch sleeps + re-resolves; a new `tests/test_ndi_receiver_loop.py` headless test; a WR-04 retry assertion added to `tests/test_atomic_io.py`.

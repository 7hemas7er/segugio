<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-provided footage dir → cataloguer | A footage path + clip files are user input scanned at ingest time |
| clip_manifest.yaml → process | The manifest is parsed by later phases to resolve clip paths |
| user footage → git repo | Real competition footage may not be license-clear / may be large |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03a | Tampering | path traversal via footage dir / manifest `file` entries | mitigate | Resolve clip paths with `pathlib` RELATIVE to the fixtures root and reject/flag entries that escape it (a `..` traversal resolves outside `tests/fixtures/` → "fixture not present locally" / refuse). Footage dir is a CLI arg, never interpolated into a shell. |
| T-01-03b | Tampering / RCE | YAML parsing in fixtures.py (manifest) | mitigate | `yaml.safe_load` ONLY for the manifest (acceptance criterion greps `yaml.load(` == 0). |
| T-01-03c | Information disclosure (rights) | committing user footage to git | mitigate | Binaries gitignored (rule from 01-01); only manifest + README committed; README documents consent/license. Test asserts `git check-ignore` ignores binaries but keeps README/manifest (Pitfall 4). |
| T-01-03d | Denial of Service | corrupt/unreadable clip crashing the cataloguer | accept | Cataloguer is a one-shot DEV tool (not the live loop); a bad clip yields a probe with zeros / a logged skip, not a process-wide crash. Low impact — re-run after fixing the file. |
</threat_model>
